# 제주대학교 교수진 안내 (jejunu-faculty)

학과를 선택하면 해당 학과의 전임교원(교수·부교수·조교수) 목록과 세부 전공, 연락처, 대표 논문을 보여주는 정적 웹 앱입니다.
프레임워크 없이 순수 HTML / CSS / JavaScript로 작성되었고, 데이터는 Google 스프레드시트에서 읽어옵니다.

## 구조

```
index.html          화면 뼈대
styles.css          디자인 토큰(색·타이포·간격), 라이트/다크 테마, 반응형
app.js              데이터 로딩(Google Sheet → CSV 파싱), 해시 라우팅, 렌더링
data/professors.json  시트를 읽지 못할 때 쓰는 백업 데이터
data/professors.csv   같은 내용의 CSV (시트 초기 입력용)
data/photos/          리포지토리에 저장한 교수 사진 (<dept_id>/<영문이름-slug>.jpg) + manifest.json
apps-script/Code.gs   선호도 저장용 Apps Script (시트에 붙여 넣어 웹 앱으로 배포)
```

## 데이터 관리 (Google 스프레드시트)

시트 한 장에 교수 한 명이 한 행입니다. 열 이름은 아래와 같고, 첫 행(헤더)은 그대로 두어야 합니다.

| 열 | 설명 |
|---|---|
| `dept_id` | 학과 식별자 (영문, 예: `foodse`, `chemeng`). 같은 학과는 같은 값 |
| `dept_name`, `dept_name_en`, `dept_url`, `dept_color` | 학과명, 영문명, 학과 홈페이지, 학과 대표색(hex) |
| `name`, `name_en`, `rank`, `order` | 이름, 영문명, 직위(교수/부교수/조교수), 학과 내 표시 순서 |
| `photo` | 사진 URL |
| `office`, `phone`, `email`, `homepage`, `scholar` | 연구실, 전화, 이메일, 개인/연구실 홈페이지, Google Scholar 프로필 |
| `tags` | 전공 키워드. 세미콜론(`;`)으로 구분 |
| `summary` | 세부 전공 요약 (50단어 내외) |
| `paper1` … `paper5` | 대표 논문. `제목 | 저널 | 연도` 형식 |

새 학과를 추가하려면 `dept_id`가 새로운 행을 넣기만 하면 첫 화면에 학과 카드가 자동으로 생깁니다.

### 사진

`data/photos/manifest.json`에 적힌 사진(`<dept_id>/<slug>.jpg`, slug는 `name_en`을 소문자·하이픈으로 바꾼 값)이 있으면 시트의 `photo` URL보다 먼저 사용하고, 로컬 사진 로딩에 실패하면 시트 URL로 대체합니다. 학과 홈페이지 사진 링크가 바뀌거나 막혀도 앱이 계속 사진을 보여주도록 하기 위한 장치입니다. 새 교수 사진을 추가하면 `manifest.json`에 `"<dept_id>/<slug>"`를 한 줄 추가하세요.

### 시트 공개 설정 (앱이 읽을 수 있게)

1. 스프레드시트 우측 상단 **공유** → **일반 액세스**를 **링크가 있는 모든 사용자 – 뷰어**로 변경
2. `app.js`의 `CONFIG.SHEET_ID`가 시트 URL의 `/d/…/edit` 사이 값과 같은지 확인

앱은 30분 동안 브라우저에 데이터를 캐시합니다. 시트를 고친 뒤 즉시 확인하려면 주소 뒤에 `?nocache=1`을 붙여 여세요.

## Google 로그인 (선택)

`app.js`의 `CONFIG.AUTH.CLIENT_ID`에 OAuth 클라이언트 ID를 넣으면 첫 화면에 Google 로그인 게이트가 생깁니다. 비워 두면 로그인 없이 동작합니다.

1. [Google Cloud 콘솔](https://console.cloud.google.com/) → 프로젝트 선택(또는 새로 만들기)
2. **API 및 서비스 → OAuth 동의 화면**: 사용자 유형 *외부*, 앱 이름·지원 이메일 입력 후 저장. (테스트 상태로 두면 *테스트 사용자*에 등록한 계정만 로그인 가능하니, 여러 사람이 쓰려면 **앱 게시**를 누릅니다.)
3. **API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**
   - 애플리케이션 유형: *웹 애플리케이션*
   - 승인된 JavaScript 원본: `https://yungbyun.github.io` (로컬 테스트용으로 `http://localhost:8080` 추가 가능)
   - 리디렉션 URI는 비워 둠
4. 만들어진 **클라이언트 ID**(`xxxx.apps.googleusercontent.com`)를 `app.js`의 `CONFIG.AUTH.CLIENT_ID`에 붙여 넣습니다.
5. 허용 범위를 정합니다.
   - `ALLOWED_DOMAINS: ['jejunu.ac.kr']` → 해당 도메인 메일은 모두 통과
   - `ALLOWED_EMAILS: ['someone@gmail.com']` → 특정 계정만 추가 허용
   - 둘 다 비우면 Google 로그인만 하면 누구나 통과
6. 로그인 상태는 브라우저에 `SESSION_HOURS`(기본 7일) 동안 유지되며, 우측 상단 **로그아웃**으로 해제합니다.

> 정적 사이트이므로 이 로그인은 *화면 접근*만 막습니다. 데이터(Google 시트, `data/` 폴더)는 URL을 알면 여전히 내려받을 수 있으니, 데이터 자체를 보호해야 하면 백엔드가 필요합니다.

## 선호도(확·중·모·부·비) 저장

학과 화면의 교수 카드 오른쪽 위(모바일은 카드 하단)와 상세 창에서 `확 / 중 / 모 / 부 / 비`를 고를 수 있습니다.

| 값 | 뜻 | 점수 |
|---|---|---|
| 확 | 확실 | 3 |
| 중 | 보통 | 2 |
| 모 | 모름 | 1 |
| 부 | 부정(negative) — 가장 낮은 선호도 | −1 |
| 비 | 비해당 — 연구년 등으로 이번 평가 대상에서 제외 | 없음(평균·키워드 분석에서 제외, 평가 완료로는 집계) |

같은 값을 다시 누르면 해제됩니다. 예전에 저장된 `상`/`하`는 앱과 Apps Script가 읽을 때 자동으로 `확`/`모`로 바꿔 읽으며, 시트 값 자체를 한 번에 바꾸려면 Apps Script 편집기에서 `migrateRatings` 함수를 실행하면 됩니다. 선호도는 로그인한 계정별로 따로 저장되며, 학과 화면의 선호도 필터와 첫 화면의 학과별 집계에 반영됩니다.

`CONFIG.RATINGS.API_URL`이 비어 있으면 브라우저(localStorage)에만 저장됩니다. 기기 간에 공유하려면 Google 시트에 저장하는 Apps Script 웹 앱을 한 번 배포합니다.

1. 데이터 시트("제주대 교수진 데이터")를 열고 **확장 프로그램 → Apps Script**
2. 편집기의 기본 코드를 지우고 `apps-script/Code.gs` 내용을 붙여 넣은 뒤 저장(💾). `CLIENT_ID`가 `app.js`의 값과 같은지 확인
3. 오른쪽 위 **배포 → 새 배포 → 유형 선택(⚙) → 웹 앱**
   - 설명: 아무 이름
   - 다음 사용자 인증 정보로 실행: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자**
   - **배포** → 권한 승인 창이 뜨면 본인 계정 선택 → "확인되지 않은 앱" 화면이 나오면 *고급 → (프로젝트명)(으)로 이동* → 허용
4. 표시되는 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 `app.js`의 `CONFIG.RATINGS.API_URL`에 붙여 넣고 push
5. 시트에 `ratings`·`settings` 탭이 자동으로 생기고 `email, dept_id, slug, name, rating, updated_at` 형식으로 쌓입니다.

### 만남 횟수 · 메모

교수 상세 창에는 선호도 칩 아래에 **만남 횟수**(−/+ 버튼)와 **메모** 상자가 있습니다. 횟수는 누르는 즉시, 메모는 입력을 멈추고 0.8초 뒤(또는 창을 닫거나 화면을 떠날 때 즉시) 시트에 저장되며, 상자 아래에 "저장 중… / 저장됨 ✓"가 표시됩니다. 카드에는 "만남 N회", "메모" 배지가 붙습니다. 시트 `ratings` 탭의 `met`, `memo` 열에 저장되고(예전 6열 시트에는 열이 자동으로 추가됨) 선호도와 같은 방식으로 여러 기기 간에 동기화됩니다. CSV 내보내기에도 두 열이 포함됩니다.

### 여러 기기 동기화

시트가 기준(source of truth)입니다. 앱은 처음 열 때, 탭·창이 다시 보일 때(잠금 해제·탭 전환·창 포커스·네트워크 복구), 그리고 화면이 보이는 동안 `CONFIG.RATINGS.SYNC_SEC`(기본 60초)마다 시트를 다시 읽어 다른 기기에서 바꾼 값을 그 자리에서 반영합니다("다른 기기의 선호도 N건을 반영했습니다"). 저장에 실패한 항목은 서버 값으로 덮어쓰지 않고 다음 동기화 때 자동으로 다시 올립니다. 시트 연동 전에 브라우저에만 저장돼 있던 값은 로그인 후 첫 동기화 때 시트로 올라갑니다("이 기기의 선호도 N건을 시트로 동기화했습니다"). 같은 기기의 다른 탭에서 바꾼 값도 바로 반영됩니다.

칩을 누르면 화면은 즉시 바뀌고 같은 순간 시트로 저장 요청이 나갑니다(칩 묶음이 파란 테두리로 깜빡이다 초록으로 바뀌면 저장 완료, 하단에 "시트에 저장됨 ✓ 시각"). 같은 교수를 연달아 누르면 순서대로 보내 마지막 값이 남습니다. 실패하면 1·3·8초 뒤 자동 재시도하고, 그래도 안 되면 "미저장 N건" 빨간 막대가 뜨며 값은 이 기기에 남겨 두었다가 연결·로그인이 회복되면(또는 "지금 다시 저장" 클릭) 자동으로 올립니다. 로그인 토큰은 만료 5분 전에 미리 갱신합니다.

로그인은 한 번 하면 계속 유지됩니다. 구글 ID 토큰은 1시간이면 만료되고 브라우저의 추적 방지 때문에 조용한 재발급이 자주 막히므로, 로그인을 한 번 확인한 뒤에는 Apps Script가 서명한 **앱 토큰**(기본 90일, `APP_TOKEN_DAYS`)을 받아 그것으로 저장합니다. 서명 키는 스크립트 속성 `APP_SECRET`에 자동 생성되어 서버에만 있습니다. 앱 토큰은 만료 7일 전부터 그 토큰만으로 조용히 갱신되므로 구글 창이 다시 뜨지 않습니다. 스크립트가 아직 옛 버전이면 예전처럼 구글 토큰으로 동작합니다. 앱 토큰까지 만료되는 등 정말 막힌 경우에만 하단에 "Google 로그인을 한 번 확인해 주세요" 막대가 뜨고, "나중에"로 닫을 수 있습니다.

앱은 요청마다 Google 로그인 ID 토큰을 함께 보내고, Apps Script가 Google에 토큰을 검증한 뒤 그 이메일의 행만 읽고 씁니다. 토큰은 약 1시간마다 만료되는데 저장 시점에 자동으로 조용히 재발급하며, 실패하면 하단 상태줄에 "로그아웃 후 다시 로그인" 안내가 뜹니다. `Code.gs`를 고친 뒤에는 **배포 → 배포 관리 → 수정(✎) → 버전: 새 버전 → 배포**를 해야 반영됩니다.

## 검색 결과 (data/insights/)

교수 상세 창의 "검색 결과"는 미리 모아 둔 `data/insights/<dept_id>.json`을 읽어 보여줍니다. GitHub Pages가 정적 호스팅이라 브라우저에서 검색 API를 직접 부를 수 없기 때문이며, 상세 창을 열 때 해당 학과 파일만 가져오므로 첫 화면 로딩에는 영향이 없습니다. 파일이 없는 학과는 "직접 찾아보기" 버튼(네이버뉴스·구글뉴스·Scholar)만 표시됩니다.

형식은 `{ "updated": "YYYY-MM-DD", "profs": { "<slug>": { "highlights": [...], "items": [{t,u,s,d,k}], "note": "" } } }`이고, `k`는 `news`(보도) / `notice`(학내) / `academic`(연구) / `activity`(대외) 중 하나입니다. 본인 항목은 `"self": true`로 두면 "본인입니다"만 표시됩니다. 동명이인이 섞이지 않도록 수집 시 이름과 소속(제주대·학과·전공 키워드)을 함께 검색하고, 소속이 확인되지 않은 항목은 넣지 않습니다.

## AI 융합 방향

상세 창의 "AI 융합 방향"은 그 교수의 세부 전공과 대표 논문을 바탕으로, AI·LLM을 어디에 붙일 수 있는지 한 줄 요약과 2~3개의 구체적인 아이디어로 정리한 것입니다(예전의 "대표 논문" 자리를 대신합니다). 같은 `data/insights/<dept_id>.json`에 교수별 `ai` 키로 함께 들어 있어 상세 창을 열 때 파일 하나만 더 읽습니다.

형식은 `"ai": { "sum": "한 줄 요약", "items": [{ "t": "짧은 제목", "d": "한 줄 설명" }] }`입니다. 이미 AI를 하는 학과(인공지능학과·컴퓨터공학과)는 "AI를 적용한다" 대신 **협업 접점**(수요 예측, 컴퓨터 비전, 경량·엣지 추론 등)으로 적었고, 본인(`yung-cheol-byun`)은 `self`로 두어 제외했습니다. 내용을 손볼 때는 "AI로 데이터를 분석한다" 같은 일반론 대신 기법 이름(PINN·대리모델·GNN·확산모델·베이즈 최적화·RAG 등)을 쓰고, 같은 아이디어가 여러 교수에게 반복되지 않게 합니다.

## 이름 맞히기 퀴즈

상단 메뉴의 **퀴즈**(`#/quiz`)는 사진을 보고 교수 이름을 맞히는 게임입니다. 학과 선택 칩으로 원하는 학과만 골라 출제 범위를 정할 수 있고(다중 선택, `jnu-quiz-depts2`에 저장되어 다음에도 유지됨), 선택을 바꾸면 게임이 새로 시작됩니다. 컴퓨터공학과는 기본으로 꺼져 있으며(`QUIZ_OFF_DEPTS`), 칩을 누르면 켤 수 있습니다.

학과 선택과 교수 선택은 시트의 `settings` 탭에 저장되어 기기 간에 동기화됩니다(키 `quiz-depts`, `quiz-ex`). 한쪽에서 바꾸면 다른 기기에서는 다음 동기화 때 따라오고 "다른 기기의 퀴즈 설정을 반영했습니다"가 뜹니다. 저장에 실패하면 이 기기에 남겨 두었다가 연결이 회복될 때 다시 올립니다.

그 아래 "출제 교수" 줄에서는 선택한 학과 안에서 교수를 한 명씩 켜고 끌 수 있습니다. 학과별로 "모두 / 해제" 버튼이 있고, 개별로 뺀 교수는 `jnu-quiz-ex`에 저장되어 다음에도 유지됩니다. 학과를 껐다가 다시 켜면 그 학과 교수는 모두 포함된 상태로 돌아갑니다.

입력칸 옆 **마이크 버튼**을 누르면 이름을 말해서 답할 수 있습니다(브라우저 내장 Web Speech API, 크롬·사파리 지원 / 파이어폭스 미지원이면 버튼이 안 보임). 한국어 이름은 잘못 들리는 일이 잦아서 인식 후보를 다섯 개까지 받아 확인하고, 자모 단위로 한 글자 차이까지 정답으로 봅니다. 엉뚱하게 들렸을 때는 오답으로 치지 않고 들은 말을 입력칸에 넣어 주기만 하므로 감점이 없습니다. 첫 사용 시 마이크 권한을 한 번 허용해야 하고 HTTPS에서만 동작합니다(GitHub Pages는 해당). 인식 결과는 `SpeechRecognitionResult`가 이터러블이 아니므로 `length`와 인덱스로만 읽어야 합니다(스프레드를 쓰면 TypeError로 화면이 멈춥니다). 권한 거부·무음·마이크 없음·네트워크 오류는 각각 안내 문구로 처리하고, 12초 안에 결과가 없으면 자동으로 중지합니다. 듣는 도중 다음 문제로 넘어가면 뒤늦게 도착한 결과는 무시합니다.

**다음 →** 버튼을 누르면 그 교수는 점수 없이 건너뛰고 다음 문제로 넘어갑니다. 모바일에서는 **사진을 왼쪽으로 밀어도** 같습니다(가로로 밀 때만 반응하고, 세로로 움직이면 평소대로 화면이 스크롤됩니다. 살짝만 밀거나 오른쪽으로 밀면 제자리로 돌아옵니다).

힌트 버튼을 누르거나 **사진을 누를 때마다** 학과 → 성 → 이름 첫 글자 → 두 번째 글자 순으로 열리며, 마지막 힌트에서 이름이 모두 드러나면 그 문제는 0점 처리되고 정답이 공개됩니다. 점수는 문제당 100점에서 힌트 1개당 25점, 오답 1회당 10점을 빼고 최소 10점이며, 정답을 직접 보면 0점입니다. 상단에 총점·맞힌 수·사용한 힌트 수·진행률이 표시되고, 모두 풀면 총점과 평균 점수가 나오는 결과 화면이 뜹니다. 정답을 맞힌 뒤에는 "상세 보기"로 그 교수 페이지로 바로 갈 수 있고, "처음부터 다시" 버튼은 언제든 새 게임을 시작합니다. 한글 이름과 영문명 모두 정답으로 인정합니다.

## 배포와 캐시 (version.json)

`index.html`은 `app.js`를 바로 불러오지 않고, 먼저 `version.json`(캐시 없이 매번 읽음)을 읽어 그 안의 `v` 값으로 `app.js?v=…`, `styles.css?v=…`를 불러옵니다. 그래서 push 직후 어느 기기에서든 새로고침 한 번이면 새 코드가 뜨고, 홈 화면에 추가한 앱도 옛 코드에 머물지 않습니다. 코드를 고쳐 올릴 때는 `version.json`의 `v`(예: 날짜+알파벳)를 함께 바꿔 주세요. 앱을 켜 둔 상태에서도 60초마다 확인해 새 버전이 있으면 하단에 "새 버전이 있습니다 [새로고침]"이 뜹니다(로그인·시트 연동과 무관하게 항상 동작).

화면 맨 아래에는 **새로고침** 버튼이 있습니다. 상단바에 아이콘을 두지 않으므로, 특히 로고를 감춘 모바일에서 이 버튼이 유일한 수동 새로고침 수단입니다. 누르면 보던 화면(해시)을 유지한 채 주소에 `?r=<시각>`을 붙여 이동하므로, `location.reload()`로는 캐시가 남는 아이폰 홈 화면 앱에서도 최신 코드를 받습니다.

## 분석 탭

상단 메뉴의 **분석**(`#/stats`)은 로그인한 계정의 선호도를 시각화합니다. 평가 진행률과 확·중·모·부·비·미지정 집계, 학과별 100% 누적막대(구간을 누르면 해당 학과가 그 선호도 필터로 열림), 전공 키워드별 평균 점수(확 3 · 중 2 · 모 1 · 부 −1, 비해당·미지정 제외)의 다이버징 막대, 직급별·학과별 표, 선호도별 교수 목록과 CSV 내보내기로 구성됩니다. 외부 차트 라이브러리 없이 HTML/CSS로 그리며, 시트 연동 여부와 관계없이 브라우저에 있는 선호도만으로 동작합니다.

## GitHub Pages 배포

1. GitHub에서 `jejunu-faculty` 리포지토리를 만들고 이 폴더를 push
2. 리포지토리 **Settings → Pages → Build and deployment → Source: Deploy from a branch**, Branch: `main` / `(root)` 저장
3. 1~2분 뒤 `https://<사용자명>.github.io/jejunu-faculty/` 에서 확인
